# l10n — design

A cross-language localisation library: **verified C#/TypeScript conformance, on-device (no API call), tree-shakable, typed.** Personal open-source (destined). Builds on `f8n` (identity/money) and is generated by `c5n` (shared codegen). See `../f8n/DESIGN.md`, `../c5n/DESIGN.md`.

## North star (every decision serves these)
1. **Verified cross-language conformance** — C# and TS produce identical output, **verified against a comprehensive shared fixture set** (not "provably identical for all inputs" — the guarantee is exactly the fixtures' coverage; see Formatting model).
2. **On-device, no API** — formatting logic + locale data baked into the libs; no network round-trip, no runtime service, no failure mode.
3. **Tree-shakable** — ship only the locales and messages you actually use; no fat bundle.
4. **Typed** — message access is strongly typed; wrong or missing params are compile errors.

## The gap it fills
Existing i18n is one of: API/runtime-based (drift-prone, network-dependent), a fat on-device bundle, or no cross-language guarantee at all. This gives all three at once — which ≈ doesn't exist.

## Settled by adjacency
Much of the original agenda is fixed by decisions in `f8n`/`c5n`:
- **Source of truth → YAML**, en-GB authoritative (dev contact point), **namespaced per scope** (shared / team / UI chrome / per-app).
- **Codegen → `c5n`** (the shared Go engine) — `l10n` feeds it templates + schema; it does *not* build its own generator.
- **Locale identity → `f8n`** (`Locale`: parse / canonicalise / match). `l10n` builds *presentation* on it; identity is not `l10n`'s (putting identity here is the tempting mistake: matching and canonicalisation have no presentation concern).
- **Formatting data → CLDR** — patterns, plural rules, display names; **derived from source and baked** (kills the OS/version/runtime-ICU drift).
- **Conformance → the golden-vector / fixtures hub** from `c5n` — one language-neutral fixtures file, each target must produce identical output per input.
- **Money/Currency/Percentage** formatted here consume `f8n`'s types (presentation lives in `l10n`, the types in `f8n`).

## Formatting model — conformance by *verification*
The crux (l10n's analog of f8n's money-arithmetic problem): **identical formatting across C# and TS, on-device, without trusting platform ICU** (`CultureInfo`/`Intl` wrap ICU, which drifts by version/OS). The approach is **conformance-by-verification, not by-construction:**

- **Derive locale data from CLDR and store it** — this pins the *biggest* variable (the data), independent of the runtime's bundled ICU.
- **Format using the language's own features, *directed by* that stored data** — don't reimplement ICU's engines.
- **Fixtures keep it honest** — the shared fixtures file is read by each target; identical output per input is the test. Where platforms diverge, fix (special-case or own that bit).

**Asymmetry to design around — JS is the awkward side.** .NET's formatters *accept* injected locale data (`NumberFormatInfo` separators/patterns, `DateTimeFormatInfo`), so C# can be "directed from source". But **`Intl.NumberFormat`/`Intl.DateTimeFormat` accept only structured *options*** (fraction digits, `style`, `useGrouping`, `signDisplay`) — **not** the glyphs (separators, symbol, pattern layout), which come from the runtime's own ICU by locale. So for data-directed formatting on JS you either reassemble via **`formatToParts`** or apply the baked CLDR pattern yourself. In practice: a **thin shared pattern-applier fed by baked data** for the data-directed formatters, delegating only stable primitives. **That applier + the baked data is the conformance surface** the fixtures police (l10n's "the whole claim rests on divide-with-rounding").

**Exactness end-to-end — never touch a float.** The minor→decimal conversion is **`f8n`'s**, not `l10n`'s — it is scaled-integer arithmetic, not presentation (`../f8n/DESIGN.md` → *The representation model*). `l10n` formats the string it is handed and never derives the digits itself. `toDisplayAmount(money): string` returns an **exact decimal string** (built in bigint/string), *never* a JS `number` — `Number(bigint)` is lossy above 2^53 (~£9bn at any real scale) and re-introduces the float error the fixed-point `Money` exists to prevent. Modern `Intl.NumberFormat.format(string)` (NumberFormat v3, Node 18+/current browsers — verify runtime baseline) formats a decimal string exactly. Shared invariant both sides obey: **format from the exact decimal, never via a binary float.**

**Currency symbol — baked glyph, locale placement.** Symbol from `f8n`'s `Currency` (baked → no ICU symbol drift), but **position/spacing/sign are locale data** (prefix `£1.50` vs suffix `1,50 €`). So `formatToParts` + **swap the currency part** (ICU decides placement, you inject the baked symbol) — *not* prepend (prepend is only right for prefix locales). Edge: a currency ICU doesn't know → fall back to a baked CLDR currency pattern.

**Plurals — evaluate the rules, do not bound them by "complexity".** Evaluate baked **CLDR plural rules** (categories `zero/one/two/few/many/other`) and own it, since platform plural APIs vary or are absent. Same for select/gender if in scope.

*This previously read "handle up to Welsh complexity, no more exotic", and that bound is withdrawn (2026-08-27): it measures **category count**, which is the wrong axis. Worth saying why it looked right — within a Western-European set (en, fr, de, es, nl, it) category count **is** a decent proxy for difficulty, because those locales' categories all mean roughly what they say. The proxy holds until the set widens, and then fails silently rather than loudly.* Welsh has six categories with straightforward semantics — `zero` is `n = 0`, `two` is `n = 2`. **Latvian has three** and is the one that breaks naive implementations, because its `zero` matches `n % 10 = 0 or n % 100 = 11..19` — 0, 10, 11…19, 20, 30. Under a "no more exotic than Welsh" rule Latvian reads as *simpler* and passes straight through. **Complexity is not how many categories a language has; it is how far a category's membership diverges from its name.** Since the rules are data and the evaluator is one walk over them, there is nothing to bound anyway — the restriction that matters is on the *driver* (an integer), not on the locale.

**The guarantee is the fixtures' coverage** (oracle caveat, as in `c5n`): parity to thin fixtures = a *shared, invisible* blind spot. So the real work is **fixture coverage** — locales × formatters × the edges that break: negatives, zero, very large/small, symbol placement, per-currency fraction digits, plural-category boundaries, RTL.

### Fixtures come in two tiers, and only one needs curating
The oracle caveat above applies unevenly, because **for plural rules the authority supplies the
test data as well as the rule.**

**Tier 1 — rule fixtures, generated, every locale.** CLDR publishes sample values inline with
each plural rule: Welsh's `other` carries `@integer 4, 5, 7~20, 100, 1000, 10000, 100000…`, and
every category in every locale does the same. That is an input → expected dataset written by
the authority, so the evaluator can be tested against **all ~200 locales** with **no locale
chosen, no expected value authored, and nobody who reads the language involved.** Latvian,
Breton, Manx and Sorbian arrive by construction, which is exactly the class this design keeps
getting caught by.

It is also the one place in the stack where the **oracle caveat genuinely weakens**. Elsewhere
— and explicitly in `../c5n/DESIGN.md` — green proves every language agrees with *our* dataset,
never that the dataset is right. Here the dataset is CLDR's, so agreement is with the authority
rather than with ourselves. Compare `f8n`, where *"for most of what is under test there is no
external authority"*; for plural selection there is, and it ships the vectors.

*Assert rather than assume:* the extractor should check that the samples actually exercise each
rule's distinguishing clauses — Latvian's `zero` samples must include 10, 11–19 and 20, not
only 0 — and fail if a rule's samples cannot separate it from its neighbours. They are curated
to be representative, which is not the same as guaranteed to be.

**Tier 2 — formatting and translation fixtures, curated.** Here expected values must be
*authored*, so the set has to be small and someone has to be able to verify it. Locales earn
their place by the **axis they cover**, and the reason is recorded so the set cannot be tidied
down later by someone who cannot see what each one was for.

| locale | the axis it covers |
|---|---|
| **cy** Welsh | plural breadth — six categories, and ordinals that differ from its cardinals |
| **de** German | layout — compound words break the widths everything else fits in |
| **fr** French | **legibility to the author** — one non-English locale that can be sanity-checked by eye. Underrated: without it, every fixture is a string nobody in the room can read |
| **hi** Hindi | *(to add)* three axes at once — the **lakh/crore magnitude ladder** (load-bearing now that compact display is in scope), **2-2-3 grouping** (`1,23,456`), and Devanagari digits |
| **ar** Arabic | *(to add)* **RTL**, which the coverage list names and no locale currently supplies — plus Arabic-Indic digits, the trap `f8n`'s `LocalDate` already had to defend against |
| **ja** Japanese | *(to add, lower priority)* the **degenerate case — a single category** (`other`), the opposite edge from Welsh, plus the 万/億 ladder |

**Latvian is deliberately not in tier 2.** It is covered for free in tier 1, which is where its
risk actually lives; adding it here would buy an end-to-end render of a deviant category at the
cost of a translation nobody present can verify. Take the free win, spend the curation budget
on **hi** and **ar**, whose axes no amount of rule-testing reaches.

**The standing rule for tier 2: every locale is in the set for a named reason, written here.** A
set assembled by reach rather than by failure mode is the one that ships the Latvian bug — the
languages that break implementations are rarely the ones with the most speakers.

## Format / parse — the boundary & the API
**Value-formatting lives in `l10n`, not on the `f8n` type.** `f8n`'s `Money`/temporal types carry only **invariant serialization** (exact, culture-free — wire/logs/debug; the grammar is pinned in `../f8n/DESIGN.md` → *Wire format*, and it is **strict in both directions** — the leniency below is the *human* boundary and must not share a parser with it). All **locale-aware format *and* parse** is `l10n`, *imported where used*:
- **TS:** free functions — `formatCurrencyShort(money, locale)`, `parseCurrency(str, locale)`. A `<MoneyInput>` (`../lattice/`) imports them and applies to the bound `Money` (idiomatic; binding unaffected). *(Named `MoneyInput`, not `CurrencyInput` — the bound type is `Money`; `Currency` is a separate primitive, and that name reads as a currency picker.)*
- **C#:** extension methods → `money.Format(locale)` reads like a method (a `using` brings them in scope).
- **Why not methods on `Money`:** tree-shaking (north star). Formatting-as-imported-functions bundles only the formatters you use; methods on `Money` would drag the whole formatting engine + CLDR data into every bundle that touches `Money`. (Also: a `Money.format` that quietly means *one* locale's short format is a convenience, not a model.)

**The locale never supplies the currency.** Every signature above takes *both* a `Money` and a `locale`, and that is load-bearing rather than incidental: the currency comes from the **amount**, and the locale decides only how it is shown. Inferring one from the other — rendering a USD amount with `£` because the viewer is `en-GB` — is the silent internationalisation failure, the kind that formats cleanly and reads plausibly and is wrong. The API shape is what makes it unavailable. The two axes are orthogonal, and the only territory→currency link is `Country.defaultCurrency`, which is a form pre-fill and not a rule about an amount that already exists. Note also that presentation varies by locale *and* currency **together** — USD is `$` in `en-US` and `US$` in `en-GB` — so neither one alone determines the rendering. See `../f8n/DESIGN.md` → *Currency and locale are orthogonal*.

**Cash rounding is not a formatting concern.** CHF rounds to 0.05 in cash but carries two decimal places for accounting. That is a fact about the *value* and belongs to `f8n` (an explicit `Money.RoundToCash`, not a display rule) — a formatter that quietly rounded to a cash scale would be changing the number it was asked to render. `l10n` shows what it is given.

**`currency-short` = compact** (`£1.2k`), **not** narrow-symbol. A **display + human-input** pair, **lossy** (`£1,234 → "£1.2k"`, so parse∘format ≠ identity) — **never a wire/persistence format**. Compact is deep: the *magnitude grouping* is locale-specific (en `k/M/B`; Indian **lakh 10⁵ / crore 10⁷**; CJK **万 10⁴ / 億 10⁸**) and CLDR compact forms are **plural-sensitive** → pulls in baked compact data + the plural machinery.

### Compact — short form, both directions
*(Resolved 2026-08-27. An earlier reading of this deferred display as "weeks of work"; that
estimate was priced on a cost that turns out not to apply, and is withdrawn below.)*

**The blocker was count-indexed patterns, and they are in the *long* form only.** CLDR's
compact patterns are keyed per locale × magnitude × plural category, which suggested display
would need category selection — and therefore the `c`/`e` compact-exponent operands, reinstating
exactly the machinery the integer-only plural restriction had removed.

Verified against `cldr-json` for **Welsh**, which is the hard case at six categories:

| form | 1000 | 10000 | 1000000 |
|---|---|---|---|
| **short** | `0K` for **every** count | `00K` for every count | `0M` for every count |
| long | `0 mil` / `0K` **by count** | `00 mil` / `00K` **by count** | `0 miliwn` (one, other) |

**Short compact is count-invariant; long compact is not.** Which stands to reason —
abbreviations do not inflect. So the short form needs **no plural selection, no `c`/`e`
operands, and does not touch the integer-only restriction.**

**Both directions, and they share almost everything.** Input reverses to display:

- **The table** — magnitude → suffix, per locale. Needed for input regardless.
- **Bucket selection** — the largest magnitude ≤ the value. Trivial.
- **Rounding** — **we own the rule.** Compact display must be locale-appropriate and *identical
  across our two languages*; it need not be byte-identical to ICU. A specified simple rule
  replaces CLDR's significant-digit subtleties.
- **No special-casing for Indian or CJK ladders** — CLDR keys by magnitude (`10000` → 万,
  `100000` → lakh), so a non-decimal ladder is just different entries in the same table, not a
  different algorithm.

**Input specifics.** Applied *after* the locale's decimal and grouping handling, in the lenient
input grammar `l10n` already owns; case-insensitive; **exact**, never floating — the multiplier
is integer scaling over the decimal string, so `1.2k` is exactly 1200. The currency's scale
still governs, so `1.000005k` fails validation for GBP exactly as `1000.005` would. No new
rule, and it stays in `parseCurrency` rather than becoming a hint, so it touches nothing in the
message DSL or the codegen shape.

**Assert the invariance; do not assume it.** The count-invariance above is read from one
language, however hard a case it is. **The extractor must check it across every locale and fail
if any short pattern differs across counts.** That converts an inference into a checked
invariant: a future CLDR change surfaces as a build failure rather than as a wrong suffix in a
locale nobody tests, and the decision of what to do about it is taken then, with the evidence
in hand. It also removes the need for a "supported locales" fallback — if the assertion holds,
every locale works.

**Long compact stays out.** That is where the plural machinery genuinely lives, and "1.2
miliwn" in prose is a different feature with a different cost. `currency-short` therefore means
**short** compact, in both directions.

**The asymmetry that was previously accepted is no longer needed.** With display in scope,
`1.2k` in and `£1.2K` out are the same table read both ways — though compact remains **lossy**
and never a wire or persistence format, so `parse ∘ format ≠ identity` still holds.

**Format is strict, parse is lenient — separate specs, not inverses.** Output = one canonical form per input (fixtured, exact). Input = a deliberately permissive human-input grammar per locale (case, whitespace, locale decimal separator `1,2k` vs `1.2k`, accepted suffixes). **Real parsing is narrow — only compact money + decimal (`1.2k`).** Everything else is lightweight **input hygiene** (char restriction, trim), not parsing; **date/time is format-only** (pickers hand back an `IsoDate` — no ambiguous free-text date parsing); `plural`/`select`/`enum` don't parse.

**Parse lowers text to digits; `f8n` converts them.** The split follows the same rule as formatting — `l10n` owns the **locale grammar** (separators, symbol, grouping, suffixes, whitespace, case) and lowers what the user typed to a plain decimal string; `f8n` converts that to minor units and decides whether it fits the currency's scale. So `l10n` never divides by `10^dp`, and never decides what is representable. When the value does not fit — `12.345` in GBP — `f8n` returns a **validation failure**, and `l10n`'s job is to render it in the user's locale ("GBP has 2 decimal places"), not to invent the rule or quietly round. Short input pads and redundant zeros are free (`12.3` and `12.3400` are both accepted), because the test is on the value, not the keystrokes — see `../f8n/DESIGN.md` → *The representation model*.

**Display formatting and edit formatting are different functions (2026-08-22).** A displayed value is fully decorated (`£1,234.57`); a value being *typed into* usually suppresses or carefully manages grouping so the caret does not jump under the user. Both are l10n's, and a money input consumes both — expose them as such rather than making the component reconstruct one from the other.

**A plain-decimal money parse is in scope (2026-08-22) — a bounded addition.** The "real parsing is narrow" line above holds for *compact* forms, but a money input needs ordinary locale-aware decimal parsing: `1,234.57` (en-GB) versus `1.234,57` (de-DE) — strip grouping, map the locale decimal separator, validate the fraction digits against the **currency's** decimal places, produce exact minor units. That is materially more than "input hygiene" and materially less than a general number grammar. The surrounding boundaries are unchanged: **no free-text date parsing** (pickers hand back an `IsoDate`), no general number grammar, `plural`/`select`/`enum` still don't parse. Consumer + editing-state model: `../lattice/DESIGN.md` → *Flagship: `MoneyInput`*.

## Interpolation & hints
One universal construct: **`{arg:hint}`** — `arg` names the parameter, `hint` selects the formatter. `"{limit:currency} per institution"`.

**The hint *is* the type.** Each hint maps to an `f8n` type, so `c5n` emits a typed parameter — `{limit:currency}` → `limit: Money`. Pass the wrong type or omit it → **compile error**. That's where the "typed" north star comes from.

**Value hints** — `hint = name ('-' param)?`, where `param` is an integer (digit count) *or* a variant keyword:
| hint | type | param |
|---|---|---|
| `currency`, `currency-short`, `currency-N` | `Money` | `short` = **short** compact (`£1.2K`), both directions — see *Compact*; `N` = display dp (e.g. `currency-0` whole-pound) |
| `number`, `number-N` | `FixedDecimal`/number | `N` = fraction digits |
| `percent-N` | `Percentage` | `N` = fraction digits |
| `date-{variant}` | `f8n.IsoDate`/`DateOnly` | CLDR lengths `short`/`medium`/`long`/`full` |
| `time-{variant}` | `f8n.IsoTime`/`TimeOnly` (timestamp → `IsoDateTime`) | CLDR lengths |

**Selectors — `plural` in the message, `select` in the shim** *(resolved 2026-08-27; they used to be one construct, and nesting is removed)*.

```
{count:plural|one={count} item|other={count} items}
```

**Only `plural` is a message construct**, and selector text no longer nests. The discriminator is that **`select` keys are locale-invariant** (`male`/`female`/`other` are the same everywhere) while **plural categories are locale-varying** (two in English, six in Welsh, decided per locale, not by the author). That maps onto the two trees: the shim tree is locale-neutral, the data trees are per-locale, and each selector belongs where its keys are decided.

So a `select` becomes **sibling messages plus generated dispatch**:

```yaml
invite:
  female: "{host} invites {guest} to her party"
  male:   "{host} invites {guest} to his party"
  other:  "{host} invites {guest} to their party"
```

`c5n` emits one shim, `invite(gender, host, guest)`, which switches and calls the right message. Consequences: **the parts model stays a flat list** so the interpreter loops rather than recurses; **`select`'s argument is a generated enum**, so an invalid value is a *compile error* rather than a silent fall-through to `other`; and translators receive **whole sentences** rather than the eighteen fragments a gender × Welsh-plural nest would produce — fragment assembly being the classic route to poor translation. Limits: no `plural` inside `plural`, and a `select` with many keys is data rather than a message selector. See `codegen-shape-test.md` → case 5.

- Plural drives on a **named arg** (`count:plural`, *not* an arg-less `{plural|…}`), so it knows which number selects.
- Categories are the **target locale's** set (en author writes `one`/`other`; cy expands to all six) — the translation pipeline generates the target's categories; runtime falls back to `other`.
- **Plural drives on an integer** *(resolved 2026-08-27; replaces a digit-coupling rule)*. CLDR's plural rules take operands `n, i, v, w, f, t`, where **`v` is the count of decimals *displayed*** — which is why "1" is `one` and "1.0" is `other` in English, the same number pluralising differently by how it is shown. The design previously coupled that to the format hint (`number-0` → v0), with a rule that a single digit-count must govern both a value's display and its selection. **That rule is gone, and so is the reason for it:** a plural argument is an integer, so `v = w = f = t = 0` and `n = i` structurally. Consequences — no `-N` hint is needed on a plural driver, a branch interpolates the bare `{count}`, nothing has to be enforced, and **the interpreter evaluates one operand rather than six** (Latvian's `v = 2 and f % 100 = 11..19` clause is structurally dead). *This is a **restriction**, not an approximation: for every input it accepts, the CLDR rules reduce exactly. A class of message simply cannot be written.* **The seam that reopens it** is fractional pluralisation, which arrives only with **long-form unit names in prose** ("2.5 kilowatt-hours"); unit *symbols* do not pluralise, so unit formatting alone does not reopen it. See `codegen-shape-test.md` → cases 3 and 13.

**Escaping — the grammar does 95%, a 3-char escape set does the rest.**
- **Prose is literal by context:** `|` `=` `:` are only structural *inside* `{…}`; in message text they're plain characters.
- **First-occurrence splits:** first `:` splits `arg`/`hint`, first `=` splits `category`/`value` — everything after is literal (so `one=you owe = £5` just works).
- **Minimal escapes:** `\{` `\}` (literal braces, since `{` always opens an interpolation) and `\|` (literal pipe *inside a selector value*; a pipe inside nested `{…}` is already unambiguous). Plus `\\`. **Backslash, not ICU `'…'` quoting** — apostrophes are everywhere (`l'eau`) and ICU's quote rules are notoriously confusing.
- Riders: **fixtures must cover escapes** (literal `{`/`|`/`\` per locale — the archetypal demo-passes-prod-breaks bug); the **translation pipeline protects structural tokens** — extract placeholders → translate prose only → reinsert (never let the LLM "translate" `{count:number}` or the escapes).

**Digits are static** (authoring-time, e.g. `percent-2`) — not a runtime arg; genuine variable precision is served by the value's own `FixedDecimal` scale ("format to the value's scale"), keeping the hint a fixed type/format. **Exact-value matches supported** — `=0`/`=1` checked *before* the category rules (`=0=No items` — distinct from the `zero` *category*, which is grammatical/Welsh-Arabic); parse wrinkle: a key starting with `=` splits on the *second* `=`. *(Also resolved: `date-*` → `f8n.IsoDate`/`IsoTime`/`IsoDateTime`; `currency-short` = **compact** — see Format/parse.)*

## Codegen structure (candidate — 2026-07-04)
How `c5n` emits l10n, from the c5n l10n stress-test. **Candidate** — a codegen-native redesign, deliberately *not* the conventional translation-client / string-resolver shape, which retrofits codegen onto a hand-first design; this is designed *for* codegen from day one. **Not yet validated against a real message set — pressure-test before settling: `codegen-shape-test.md`.**

Three parts:
- **Generated — a `tree<T>` of typed shims.** *(And the shims now carry `select` dispatch — see* Selectors *above; the parts model below is consequently a flat list rather than a tree.)* The namespace tree (dir/file = namespace) emits as nested scopes (C# nested static classes, TS nested modules); each message leaf is a **thin typed façade** whose signature comes from the hints (`{limit:currency}` → `limit: Money`), delegating to the runtime. The typed signature is the one irreducibly-generated thing — the "typed" north star.
- **Generated — the message as *data*.** The parsed `{arg:hint}` message (params + a recursive list of parts: `literal | format-call | selector`) emitted as a plain data value. `c5n` never parses the DSL; an **l10n front-end lowers it to this structured model** upstream.
- **Hand-written — one `render` interpreter per language.** Walks the parts, calls the formatters, evaluates plural category, recurses into selector branches — plus the formatters + pattern-applier + `PluralCategory`. **This is the entire conformance surface** (exactly "conformance by verification"): language-neutral message data + two hand-written interpreters, fixture-tested.

**Why (perf + conformance):** the DSL is parsed to data **at build time**, so runtime never re-parses (a runtime resolver would, per call); a **single** interpreter per language keeps the conformance surface tiny — vs inlining thousands of message bodies, the cross-language-identical burden the north star can least afford. Near-inlined speed, minimal surface, simple codegen. See `../c5n/DESIGN.md` → **Stress-tested against l10n**.

**Open (C#):** nested static classes give typed access, but shipping only *used* locales is the separate satellite-assembly / trimming question (Tree-shaking agenda item).

**Correction from the pressure test (2026-08-27): the three parts above describe *one* tree where there are two.** The **typed-shim tree is locale-neutral** — one of it, signatures derived from the canonical (en-GB) hints — while the **message-data trees are per locale**, since Welsh carries six plural branches where English carries two. Different leaf types, different output layouts, different tree-shaking needs, emitted by `c5n` from related but distinct sources. It also implies a rule this doc left unstated: **a signature derives from the canonical message only, and every locale's data must conform to it** — checkable at build time, and what makes the pipeline's *protect structural tokens, translate prose only* load-bearing rather than merely tidy, since a translator who introduced an interpolation would otherwise produce data the shim cannot call. Full case list and what is still unwalked: `codegen-shape-test.md`.

## Translation pipeline
**Machine-generates → human-gates → CD-gate**, checked-in and PR-reviewed (same shape as `c5n`'s generated code — deterministic diffs are the review surface).

**Canonical storage (en-GB) = the dev interaction point.**
- An **en-GB directory**; **sub-dirs + files provide the namespacing** (the dir/file tree *is* the namespace tree).
- Files are `key = value` **JSON**. Devs edit here.
- **Every regen sorts files by key** → deterministic ordering → clean git diffs.

**Per-locale storage** mirrors the en-GB dir/file structure. Each entry:
```json
"key": { "value": "…", "sourceChecksum": "…", "translated": "<DateTimeOffset>", "approved": false }
```

**Translation run** — iterate en-GB; per key compare current source checksum vs stored `sourceChecksum`:
- **missing or checksum differs** → call the **Anthropic API**, fill the translation, set `translated`, update `sourceChecksum`, **`approved: false`** *(the linchpin — a source change un-approves, or stale text ships past the gate)*.
- **checksum matches** → no-op.
- Placeholders: **repair `{arg:hint}` after the round trip, then validate** — the set (by identity) must match source; a *dropped* placeholder isn't repairable, so on mismatch reject/retry, never write. (Repair keeps LLM context/quality; validate backstops drops.)
- **Plurals expand to the *target's* categories** — Welsh's six from English's two; each variant translated + placeholder-checked.

**Human review** — adjust `value`, set `approved: true`. `sourceChecksum` stays pinned to what was approved, so the next source change re-gates it.

**Deploy gate** — blocks release if *any* string is unapproved.

**Housekeeping & choices:**
- **Orphan pruning** — a key removed from en-GB → prune the per-locale entries (the regen already rewrites every file). **Rename = delete + add → re-translate from scratch** (prior human work on the old key is lost; rename sparingly).
- **Clobber policy** — a re-translate **never clobbers**: keep the human `value`, set `approved:false`, and store the fresh machine translation in a **`suggestion`** field. The reviewer then chooses — accept their old (minor source change), take the `suggestion` (material change), or edit. Never silently overwrite, never blindly keep.
- **Context for the translator** — three tiers, cheapest first: (a) **the key path is context** (`account.open.button` → feed the full key to the LLM prompt, free); (b) an **optional `{ value, context }`** form for strings that genuinely need a note (plain `key = "value"` stays the common shorthand); (c) **a screenshot** — the best context — see the translator UI below.

## Translator UI (l10n × a11y — seam now, room later)
The pipeline's **human-gate surface**: land on a field, a shortcut opens a panel showing **key + value + per-locale status + a screenshot** of where the string renders. Edit → the app splits value/hints, stores → **creates a PR** (which flows through `approved:true` + the deploy gate). Two strong ideas:
- **Screenshot-as-context comes from the `a11y` audit.** The audit already walks the live app per-control; if controls **carry their l10n key**, it captures a screenshot per key — reusing a11y infra for l10n. (Cross-project: `a11y`'s design must include the **l10n-key ↔ control mapping**.)
- **Placeholders as atomic chips** — the human edits *around* protected `{arg:hint}` chips they can't delete or retype → placeholder integrity on the human path by construction (vs the LLM path's repair+validate).

**Seam vs room:** build the *data linkage* now — `l10n key ↔ control ↔ screenshot ↔ per-locale status`, and the a11y audit emitting the key — the full UI is a later room. Caveats: **screenshots regenerate on each audit/CI run** (else they rot); **non-visual strings** (error toasts, aria-only, un-captured states) have no screenshot → fall back to key-path + optional context.

**Compliance / trust** (`design-rigour`; customer-facing content + human gate is the right control):
- **Source strings → a third party (Anthropic)** — fine for public UI copy (display-destined), so the rule follows: **no secrets / PII / internal notes in translatable strings.**
- **Stricter-than-LLM content** — financial promotions, legal disclosures, regulatory error text: a mistranslation is a *compliance* event, not a typo. A per-string `requiresProfessional` marker (or namespace convention) routes those to a human translator, still through the same approval gate.

## Runtime & integration
Surface beyond formatting/messages (much of it C#-side glue; each item has been needed in practice):
- **Locale scope — never `CurrentCulture`.** An `IDisposable` scope sets the locale per request/loop/operation; **`AsyncLocal`-flowed** (thread-static would leak one request's culture into another across `await` — a real correctness bug). "Controlled ambient": the scope is the ergonomic default (`format(money)` reads it) with an explicit override (`format(money, locale)`). Same discipline as f8n's *injected clock, never `DateTime.Now`*. (TS has no `CurrentCulture` temptation — `Intl` takes locale per call, Vue holds a reactive ref — so this is mostly a C# discipline.)
- **m2m propagation** — locale flows across service boundaries via a header (like trace context); extensions to set/read it, so the scope survives service → service.
- **JWT locale extraction** — pull the locale claim from a JWT (both langs) → feed the scope.
- **Setup extensions** — C# DI (`services.AddL10n(…)`), Vue plugin (`app.use(…)`, plain-TS options, framework-uncoupled).
- **Analysers** — Roslyn (C#) / ESLint (TS) flag problems (hard-coded strings, missing keys, bad hints) at build.
- **Enum localization** — each enum member gets a localized label via the key convention `EnumName:Member`; typed access generated. (The "helpers (C# enums)" from the original sketch.)

## Ordinals — absent, and named as such
CLDR defines **ordinal** plural rules separately from cardinal ones (`ordinals.xml`,
`<plurals type="ordinal">`, roughly 120–130 locales). This design has no equivalent of ICU's
`selectordinal`, and until 2026-08-27 nothing recorded that the capability existed.

It is a real gap, not a rounding error: **English needs four ordinal categories** — `one`
(1st, 21st), `two` (2nd, 22nd), `few` (3rd, 23rd), `other` (4th, and 11th–13th) — where it
needs two cardinal ones. And **the same category name means different things in the two
tables**: Welsh's `zero` is `n = 0` for cardinals and `n = 0,7,8,9` for ordinals.

That last point is why ICU keeps `plural` and `selectordinal` as separate keywords — **the hint
selects the rule table**. The hint-driven model here would express it correctly the moment a
hint existed; the gap is the hint, not the architecture, so adding it later is additive.

**Deferred, not rejected.** Ordinals are rarer in product copy than they look — "1st January"
is a `date` hint's job, and rankings are uncommon — so the cost of waiting is low. What was not
acceptable was leaving it unmentioned, since an absent capability nobody has named reads as an
oversight rather than a decision. See `codegen-shape-test.md` → case 7.

## Assumptions this library can't make
A formatter with a fixed locale, a single currency and bounded amounts can be entirely correct under its own rules and still be unusable as a library. Dropping each of those assumptions is where the whole difficulty lives.
- **Multi-locale from the start** — so suffix-currency locales (de/fr) and Welsh plurals are in scope, not bolt-ons.
- **dp is currency-specific, nothing more** — the money model is `f8n`'s currency-dp-exact `Money` (a fixed 6-dp-internal convention doesn't generalise; see `../f8n/DESIGN.md`). Sub-currency precision is explicit `FixedDecimal`.
- **Any magnitude** — the library can't assume bounded amounts, so exactness must hold to arbitrary size (the `Number()`/2^53 leak stays hidden while amounts are bounded and bites the moment they aren't → exact-string throughout).
- **Any locale** — so symbol placement, grouping, plural rules are all *data*, never hardcoded (prepend-the-symbol was fine for prefix locales, wrong in general).
- **No locale set is small enough to simplify the *syntax* against** — the previous bullet is about the implementation; this one is about the design surface, and it is the one that catches people out. Across en, fr, de, es, nl and it you get `one`/`other` with an occasional `many`, **no `zero` category at all**, and no exact match beyond zero ever wanted — so every tempting shortcut in the message grammar is genuinely *correct* in a Western-European set. It stops being correct one locale further out: **Latvian's `zero` matches 0, 10, 11…19, 20**; **Breton's `two` matches 22, 32, 42 but not 12, 72, 92**; **Welsh's `zero` is `n = 0` for cardinals and `n = 0,7,8,9` for ordinals**. An *application* may bound its locales and simplify accordingly, because the set is a fact it owns. A *library* cannot — "we don't ship Latvian" is not an argument available to it — and that difference is the whole reason this design refuses shortcuts that would be perfectly defensible in a product. *(The cost falls on design, not implementation: evaluating CLDR's rules properly is the same work as evaluating a subset, so the tax is paid in decisions like `codegen-shape-test.md` → case 7, which is the cheapest place for it to land.)*

## Decisions log
- **2026-08-25 · `l10n` does no money math** → the minor↔major digit conversion belongs to `f8n` (scaled-integer arithmetic, golden-vectored there); `l10n` formats the exact decimal string it receives and never derives digits. Two implementations would be two conformance surfaces obliged to agree, precisely where a float silently ruins the answer. **Parse mirrors it:** `l10n` lowers locale text to a plain decimal string, `f8n` converts and enforces the currency's scale, and an unrepresentable value comes back as a **validation failure** `l10n` localises ("GBP has 2 decimal places") — never a silent round. Short input pads; redundant trailing zeros are accepted; the test is the value, not the digits typed.
- **2026-07-02 · Conformance by verification** → derive+bake CLDR data; format with language features directed by baked data; a shared fixtures file per target verifies identical output. Guarantee = fixture coverage, not by-construction. North star reworded "verified-identical against fixtures".
- **2026-07-02 · JS `Intl` asymmetry → thin shared pattern-applier** → `Intl` takes options not glyphs; use `formatToParts` / a baked-pattern applier for data-directed formatting. That applier + baked data = the conformance surface.
- **2026-07-02 · Exact-decimal-string formatting** → `toDisplayAmount → string` (bigint-built, exact); `Intl.format(string)`; never `Number()`/float. Invariant both sides: format from the exact decimal.
- **2026-07-02 · Currency symbol** → baked glyph from `f8n.Currency`; **locale placement via `formatToParts`-swap**, not prepend.
- **2026-07-02 · Plurals** → baked CLDR plural rules, up to Welsh, no more.
- **2026-07-02 · Adjacency** → source=YAML, codegen=`c5n`, locale-identity=`f8n`, formatting-data=CLDR-baked, conformance=fixtures hub.
- **2026-07-03 · Interpolation grammar** → one construct `{arg:hint}`; **hint = the generated param type** (compile-time safety). Value hints `name('-'param)?` (param = digit-count int or variant keyword); **selector** hints `plural`/`select` carry `|category=text` with nested `{arg:hint}`. Plural drives on a named arg and its category set is the *target* locale's; plural couples to display precision (digit count = the `v` operand).
- **2026-07-03 · Small opens cleared** → digits **static** (value's `FixedDecimal` scale handles variable precision); **`=N` exact-value** matches before category rules; **parse only compact-money + decimal** (`1.2k`), rest is input-hygiene, date/time format-only (pickers); **clobber → keep-human + `approved:false` + `suggestion`** (never overwrite/blindly-keep); **context = key-path + optional `{value,context}` + screenshot**.
- **2026-07-03 · Translator UI (l10n × a11y)** → the pipeline's human-gate surface: panel shows key + value + per-locale status + **screenshot from the `a11y` audit** (which tags the l10n-key ↔ control), edits → splits value/hints → PR. Placeholders as **atomic chips** (integrity on the human path). Build the *data linkage* seam now (a11y must emit the l10n key); full UI is a later room. Non-visual strings fall back to key-path/context; screenshots regen per audit run.
- **2026-07-03 · Locale scope, never `CurrentCulture`** → `IDisposable`, `AsyncLocal`-flowed, per request/loop; controlled-ambient with explicit override. Same "no ambient global" discipline as f8n's injected clock. m2m header propagation; JWT extraction feeds it. (Mostly a C# discipline — TS is naturally explicit.)
- **2026-07-03 · Runtime/integration surface** → Roslyn/ESLint analysers (hard-coded-string ban); enum localization (`EnumName:Member` keys → typed labels); setup extensions (C# DI, Vue plugin/plain-TS options); `f8n` carries JSON `fromJson`/`toJson` helpers.
- **2026-07-03 · Translation pipeline** → en-GB canonical (dir/file namespacing, sorted `key=value` JSON, dev interaction point); per-locale mirror entries `{value, sourceChecksum, translated, approved}`. Checksum diff/missing → Anthropic re-translate, **`approved:false`** (the re-gate linchpin), **placeholder repair + validate** (drop → reject/retry), plural → target categories. Human sets `approved:true` (checksum pinned). **CD gate blocks any unapproved.** Orphan-prune on key removal; rename = re-translate. *Compliance:* no secrets/PII in strings (they go to Anthropic); `requiresProfessional` marker for legal/financial-promo/regulatory. *Open:* clobber-vs-keep-human on small source change (lean keep+unapprove), optional context field. value-formatting is `l10n`, **imported** (TS free functions — tree-shakable; C# extension methods for method-feel), *not* methods on the `f8n` type (which carries invariant serialization only). Tree-shaking is the decider. `currency-short` = **compact** (display + human-input, lossy, never wire; locale-specific magnitude grouping + plural-sensitive). Format strict/fixtured; parse lenient/separate-spec.

- 2026-08-27: **nesting removed — `select` hoists into the shim, `plural` stays in the message.** The first pressure-test case to examine the codegen shape rather than the syntax, and it holds while getting simpler. The discriminator is that **`select` keys are locale-invariant and plural categories are not**, which maps straight onto the two trees: locale-neutral selection belongs in the locale-neutral shim. A `select` therefore becomes **sibling messages plus generated dispatch on an enum** — an invalid value is a compile error rather than a silent `other` — and **the parts model stays a flat list**, so the interpreter loops rather than recurses and the conformance surface does not grow. Translators get whole sentences instead of the eighteen fragments a gender × Welsh-plural nest produces, which is better practice regardless. Limits recorded: no `plural` inside `plural`; a wide `select` is data, not a message selector.
- 2026-08-27: **fixtures split into two tiers — and plural rules need no locale curation at all.** CLDR publishes sample values inline with every rule (`@integer 4, 5, 7~20, 100, 1000…`), which is an input → expected dataset written by the authority for **every locale it defines**. So the plural evaluator is testable against ~200 locales with **no locale chosen, no expected value authored, and nobody who reads the language involved** — Latvian, Breton, Manx and Sorbian arrive by construction, which is precisely the class this design kept getting caught by. It is also the one place the **oracle caveat genuinely weakens**: elsewhere green proves the languages agree with *our* dataset, never that it is right, but here the dataset is CLDR's. **Latvian is deliberately kept out of the curated tier** — its risk is already covered, and adding it would buy an end-to-end render at the cost of a translation nobody present can verify; the curation budget goes to **hi** and **ar** instead. - 2026-08-27: **withdrew the "up to Welsh complexity" plural bound, and gave the fixture locale set a written rationale.** The bound measured **category count**, which is the wrong axis: Welsh has six categories with straightforward semantics, while **Latvian has three** and is the one that breaks naive implementations (`zero` matches 0, 10, 11…19, 20). "No more exotic than Welsh" would have admitted precisely the locale that catches the bug. Complexity is how far a category's membership diverges from its name — and since the rules are data walked by one evaluator, there is nothing to bound anyway; the restriction that matters is on the *driver* being an integer. Standing rule: a locale is in the set for a named reason, written down, because a set assembled by reach rather than by failure mode is the one that ships the Latvian bug.

Long compact stays out; that is where the plural machinery actually lives. Supersedes the earlier entry deferring display, and the "weeks of work" estimate with it.
- 2026-08-27: **compact split — input in scope, display deferred with a shape rather than a date.** Display is the most expensive item in the hint table and partly undoes the plural restriction: CLDR's compact patterns are count-indexed per locale and magnitude, and selecting among them needs the `c`/`e` operands that integer-only plurals had just removed, plus locale-shaped magnitude ladders, significant-digit rounding and a table large enough to fight tree-shaking. **Input needs none of it** — a suffix → multiplier table applied in the lenient input grammar, exact integer scaling over the decimal string, with the currency's scale still doing the rejecting. Both are restrictions rather than approximations: the fallback is correct, merely longer.
