# f8n — implementation plan

The *what next*, ordered by dependency. `DESIGN.md` holds the *why*; this holds the sequence
and doubles as session handover — the next session starts at the first unchecked step. Mark
`✓` in place as steps land.

**Where it stands:** Phases A, B and C complete. Ten hand-written types across C# and
TypeScript, eight vector datasets (236 cases) running in both languages from one dataset, and
every one of them re-run under a hostile locale, and the reference tables generated by
`c5n` from committed YAML. The arithmetic core exists; the wire form does not.

## Phase A — the primitives that other things need ✓

Built in dependency order, each one hand-written twice and verified against a shared dataset
rather than against the other implementation.

- ✓ **A.1 — `Percentage`.** An exact `Rational` over big integers, apply-only. Named
  constructors (`FromPercent` / `FromProportion`) because the same digits mean two things a
  hundred apart; canonical `num/den` as the only wire form, so equal values have identical
  encodings and wire equality is value equality.
- ✓ **A.2 — `Country`, `Currency`.** Identity and reference data, generated by `c5n` from
  `data/*.yaml` into partial classes / data modules. Includes **JPY (0 dp)** and
  **BHD (3 dp)** — the two scales that are not 2, which is what stops "amount" quietly
  meaning "two decimal places" everywhere else.
- ✓ **A.3 — `LocalDate`.** The ISO 8601 calendar date and nothing else, character-walked in
  both languages. Not `DateOnly`, not `Date`: the point is that both accept and reject the
  same strings, and each language's built-in brings its own accepted forms.
- ✓ **A.4 — `EffectiveDated<T>`, `TaxRate`.** A value that changes on known dates, with an
  inclusive boundary and no extrapolation — a date before the series has *no answer* rather
  than the oldest known value. Sorts its own entries rather than trusting authoring order.
- ✓ **A.5 — `RoundingMode` and `divide-with-rounding`.** The one function the cross-language
  claim collapses onto, written once and shared. `HalfUp` rounds **away from zero** (see
  `DESIGN.md` → decisions log).
- ✓ **A.6 — `Money`.** An exact integer count of the currency's minor units. `FromMajor` is
  the wire parser — the amount grammar, strict in both directions, with `DESIGN.md`'s reject
  table transcribed into vectors.

**Checkpoint reached.** Both targets compile; 162 vector cases agree in both languages; the
net has been seen to fail on three deliberate breaks (a naive leap rule, a day-before-month
comparison, and `HalfUp` toward +∞).

## Phase B — the wire form

`Money`'s *amount* grammar exists; the JSON shape around it does not, and neither does
the rule for the types that travel beside it. This is the phase `c5n`'s generated `fromJson`
sits on top of, so it comes before any new consumer.

- ✓ **B.1 — `toJSON` / `fromJson` on the primitives.** `Money` as
  `{"amount":"12.34","currency":"GBP"}`; `Percentage` and `LocalDate` as their canonical
  strings, which already exist. Strict in both directions, sharing the parsers already
  written rather than growing second ones. Smaller than it looks outbound: only a type whose
  wire form differs from its field layout needs a `toJSON`, so containers need none. Inbound
  is one method per type, recursing through its own field types. No default-construct path;
  C# gets a `JsonConverter`. Shapes and reasoning pinned in `DESIGN.md` → *JSON*.
- ✓ **B.0 — the generated lookups, and `Find`.** `c5n` gained `lookup:`, so a table emits an
  accessor for its key and one per declared index; `Country` is indexed by alpha-2 and
  numeric as well as its alpha-3 identity, `Currency` by numeric. The **dispatcher is
  hand-written** (`Country.Find` / `findCountry`) because deciding which form a string is
  needs domain knowledge the schema does not hold. Ingestion only — the wire still takes
  alpha-3 alone.
- ✓ **B.2 — reference types travel as their key.** `Country` and `Currency` as `"GBR"` /
  `"GBP"`, resolved back through the generated key index from B.0. Wire side only: alpha-3,
  strictly, with the other forms staying on the ingestion path.
- ✓ **B.3 — enums travel as their member name.** Already decided (`DESIGN.md` → *Enums
  travel as their member name*) and already true in TypeScript by construction; C# needs
  configuring to write strings rather than the serialiser's numeric default.
- ✓ **B.4 — vectors and properties for the wire form.** Two halves doing different jobs.
  **Vectors** feed the same input to both languages and pin the exact bytes — a `toJson` case
  whose expected value is the serialised string, a `fromJson` case whose input is that string
  — which is what makes C#'s output TS-readable, transitively through the shared dataset. The
  inputs are already string-shaped, so this needs no new harness machinery. **Properties**
  carry no expected value: `fromJson(toJSON(x)) == x` and `toJSON(fromJson(w)) == w`. Reject
  cases carry the weight in the vectors, as they do for the amount grammar.

**Checkpoint reached.** A `TaxRate` serialises byte-identically in both languages — and it
carries no JSON code of its own in either, which is the point: four different rules fire in one
payload (a reference type as its key, two enums as text, a wrapper primitive as its canonical
string) with the container knowing none of them. Both C# defaults had to be corrected to get
there, and removing either correction turns that one case red while every other case stays
green: `{"Jurisdiction":"GBR","TaxType":0,…}`.

## Phase C — `allocate`

Deliberately after the wire, because nothing else depends on it and it is the largest single
piece of behaviour left.

- ✓ **C.1 — equal N-way `allocate`.** Floor each exact share to minor units, then hand out
  the leftover units by a caller-supplied `AllocationRule` — **no default**, since a silent
  apportionment method is the mandated-method non-compliance the currency-dp decision already
  guards against. Built-ins only.
- ✓ **C.2 — the three rules.** `LargestRemainder` (Hamilton, ties by ascending index),
  `Designated(i)`, `Sequential`.
- ✓ **C.3 — weighted `allocate`.** Shares as exact `Rational`s (`m × wᵢ / Σw`), floored,
  with the same remainder hand-out.
- ✓ **C.4 — the properties that were waiting for it.** `sum(allocate(m, rule)) == m` and
  `allocate(−m) == −allocate(m)`, listed in `../c5n/PLAN.md` → 3.1b and blocked until now.

**Checkpoint reached.** `£100 / 3` conserves exactly under every rule, in both languages, and
the net has been seen to fail: working on the signed total instead of the magnitude turns six
cases red at once, including *"−100.00 split 1,1,5 summed to −99.98"*.

This also closed the last dangling item from the vector work — `../c5n/PLAN.md` → 3.1b listed
`sum(allocate(m, rule)) == m` and `allocate(−m) == −allocate(m)` as properties waiting on
`Money`. They are asserted now.

## Rooms — deferred, additive

- **`FixedDecimal`** — the explicit precision space (FX intermediates, accrual, unit prices).
  `divide-with-rounding` already lives outside `Money` ready for it.
- **`ExchangeRate`, `PhoneNumber`, `Locale`** — the rest of the primitive scope.
- **Cash rounding** — CLDR carries `cashDigits` / `cashRounding` beside `digits`, and
  `Currency` models only the accounting scale, so `f8n` cannot express CHF rounding to 0.05.
  The lean is an explicit `Money.RoundToCash` over new currency fields rather than a change
  to the amount grammar, so an accounting `CHF 12.34` stays a valid value that simply is not
  payable in coins. Lands with the pipeline that supplies the data.
- **The canonical-data pipeline** — cron → diff → PR. **Ungated since 2026-08-26**; the
  licence question that blocked it resolved to CLDR-only. Replaces the hand-authored skeleton
  tables, and is what `attribution:` in `c5n.yaml` is waiting for.
- **Packaging** — npm (ESM) + NuGet, versioning, tree-shaking structure.

## Change log
- 2026-08-27: **Phase C done — `allocate` conserves, and the waiting properties are asserted.**
  Equal and weighted, three rules, sign-symmetric by construction. The implementation forced
  three decisions recorded in `DESIGN.md`, the sharpest being that the doc's "floor each share"
  is right only for non-negative totals — flooring and negating disagree, so the sign is lifted
  out instead. With Phases A–C closed, what remains in f8n is Rooms: `FixedDecimal`, the rest
  of the primitive scope, the CLDR pipeline (now ungated), cash rounding, and packaging.
- 2026-08-27: **Phase B done — the wire form works in both languages, byte-identically.**
  B.1–B.4 in one pass, because they turned out to be one thing: `Money`'s `fromJson` needs the
  currency key index, which is B.2, and the nested case needs enums as text, which is B.3.
  27 vector cases, expected values **authored from the design doc rather than captured**, and
  both implementations matched on the first run. The container case earned its place
  immediately: .NET defaults to PascalCase property names and numeric enums, so `TaxRate` —
  which has no JSON code in either language — was the one place the two silently disagreed.
  Also corrected a property statement that writing the tests exposed as overstated: the wire
  round trip holds over *canonical* encodings, not over everything `fromJson` accepts, because
  key order is not part of a value's encoding.
- 2026-08-27: **the JSON interface is pinned before B.1 is written, and "envelope" stops
  meaning two things.** `envelope:` is a `c5n` schema keyword for the fields that key a series
  entry, so this phase is now *the wire form* — the JSON shape around a value, which is a fact
  about the bytes and not a type. B.4 gains the split that matters: **vectors** feed one input
  to both languages and pin the bytes (cross-language), **properties** carry no expected value
  (per-language, catching what a fixed dataset cannot). See `DESIGN.md` → *JSON*.
- 2026-08-26: **data sourcing resolved to CLDR, and cash rounding recorded as a gap.** The
  licence question that had been gating the pipeline is closed — see `DESIGN.md` — so the
  source pipeline moves from blocked to merely unbuilt. Reading CLDR's structure to settle it
  turned up a second scale: `cashDigits` / `cashRounding` beside `digits`, which `Currency`
  does not model. Filed under Rooms with a lean rather than decided, since it lands with the
  data that motivates it.
- 2026-08-26: created, at the point f8n stopped being one type at a time and acquired a
  sequence worth writing down. Records Phase A as landed — `Percentage`, the reference
  tables, `LocalDate`, `EffectiveDated<T>`, `TaxRate`, `divide-with-rounding` and `Money` —
  and sequences what is left: the **wire form** first, because `c5n`'s generated
  `fromJson` sits on it and a new consumer would be building sideways until it exists, then
  **`allocate`**, which nothing else depends on and which unblocks the two conservation
  properties that have been listed and waiting since the vector harness was built.
