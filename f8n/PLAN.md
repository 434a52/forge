# f8n — implementation plan

The *what next*, ordered by dependency. `DESIGN.md` holds the *why*; this holds the sequence
and doubles as session handover — the next session starts at the first unchecked step. Mark
`✓` in place as steps land.

**Where it stands:** seven types hand-written in C# and TypeScript, five vector datasets
(162 cases) running in both languages from one dataset, and the reference tables generated by
`c5n` from committed YAML. The arithmetic core exists; the wire envelope does not.

## Phase A — the primitives that other things need ✓

Built in dependency order, each one hand-written twice and verified against a shared dataset
rather than against the other implementation.

- ✓ **A.1 — `Percentage`.** An exact `Rational` over big integers, apply-only. Named
  constructors (`FromPercent` / `FromProportion`) because the same digits mean two things a
  hundred apart; canonical `num/den` as the only wire form, so equal values have identical
  encodings and wire equality is value equality.
- ✓ **A.2 — `Country`, `Currency`.** Identity and reference data, generated by `c5n` from
  `data/*.yaml` into partial classes / data modules. Includes **JPY (0 dp)** and
  **BHD (3 dp)** — the two scales that are not 2, which is what stops "amount" quietly
  meaning "two decimal places" everywhere else.
- ✓ **A.3 — `LocalDate`.** The ISO 8601 calendar date and nothing else, character-walked in
  both languages. Not `DateOnly`, not `Date`: the point is that both accept and reject the
  same strings, and each language's built-in brings its own accepted forms.
- ✓ **A.4 — `EffectiveDated<T>`, `TaxRate`.** A value that changes on known dates, with an
  inclusive boundary and no extrapolation — a date before the series has *no answer* rather
  than the oldest known value. Sorts its own entries rather than trusting authoring order.
- ✓ **A.5 — `RoundingMode` and `divide-with-rounding`.** The one function the cross-language
  claim collapses onto, written once and shared. `HalfUp` rounds **away from zero** (see
  `DESIGN.md` → decisions log).
- ✓ **A.6 — `Money`.** An exact integer count of the currency's minor units. `FromMajor` is
  the wire parser — the amount grammar, strict in both directions, with `DESIGN.md`'s reject
  table transcribed into vectors.

**Checkpoint reached.** Both targets compile; 162 vector cases agree in both languages; the
net has been seen to fail on three deliberate breaks (a naive leap rule, a day-before-month
comparison, and `HalfUp` toward +∞).

## Phase B — the wire envelope

`Money`'s *amount* grammar exists; the JSON envelope around it does not, and neither does
the rule for the types that travel beside it. This is the phase `c5n`'s generated `fromJson`
sits on top of, so it comes before any new consumer.

- [ ] **B.1 — `toJson` / `fromJson` on the primitives.** `Money` as
  `{"amount":"12.34","currency":"GBP"}`; `Percentage` and `LocalDate` as their canonical
  strings, which already exist. Strict in both directions, sharing the parsers already
  written rather than growing second ones.
- [ ] **B.2 — reference types travel as their key.** `Country` and `Currency` as `"GBR"` /
  `"GBP"`, resolved back through the generated tables. Needs a lookup by key on the
  generated side — the first thing `c5n` emits that is read rather than only constructed.
- [ ] **B.3 — enums travel as their member name.** Already decided (`DESIGN.md` → *Enums
  travel as their member name*) and already true in TypeScript by construction; C# needs
  configuring to write strings rather than the serialiser's numeric default.
- [ ] **B.4 — vectors for the envelope.** Accept and reject, both directions. The reject
  cases carry the weight, as they do for the amount grammar.

**Checkpoint:** a `TaxRate` round-trips through JSON in both languages, byte-identically.

## Phase C — `allocate`

Deliberately after the wire, because nothing else depends on it and it is the largest single
piece of behaviour left.

- [ ] **C.1 — equal N-way `allocate`.** Floor each exact share to minor units, then hand out
  the leftover units by a caller-supplied `AllocationRule` — **no default**, since a silent
  apportionment method is the mandated-method non-compliance the currency-dp decision already
  guards against. Built-ins only.
- [ ] **C.2 — the three rules.** `LargestRemainder` (Hamilton, ties by ascending index),
  `Designated(i)`, `Sequential`.
- [ ] **C.3 — weighted `allocate`.** Shares as exact `Rational`s (`m × wᵢ / Σw`), floored,
  with the same remainder hand-out.
- [ ] **C.4 — the properties that were waiting for it.** `sum(allocate(m, rule)) == m` and
  `allocate(−m) == −allocate(m)`, listed in `../c5n/PLAN.md` → 3.1b and blocked until now.

**Checkpoint:** `£100 / 3` conserves exactly, under every rule, in both languages.

## Rooms — deferred, additive

- **`FixedDecimal`** — the explicit precision space (FX intermediates, accrual, unit prices).
  `divide-with-rounding` already lives outside `Money` ready for it.
- **`ExchangeRate`, `PhoneNumber`, `Locale`** — the rest of the primitive scope.
- **The canonical-data pipeline** — cron → diff → PR, gated on the `iso-codes` licence
  decision in `DESIGN.md` → *Design agenda*.
- **Packaging** — npm (ESM) + NuGet, versioning, tree-shaking structure.
